# ТЗ: веб-приложение «Дейлик»

> Техническое задание для разработки. Составлено по сообщению клиента (FL.ru №2351967: «Нужно написать простое приложение для сохранения задач на день. Желательно использовать что-то кроссплатформенное (для айфонов и андроидов). Дизайн предполагает наличие анимаций. Срок: 10 дней.»). Недостающая информация придумана и зафиксирована здесь; домыслы помечены.

---

## 1. Название продукта

**«Дейлик»** — живой daily-планировщик: задачи на сегодня, которые приятно закрывать.

## 2. Цель проекта и целевая аудитория

**Цель:** дать человеку простой способ зафиксировать дела на день и видеть свой прогресс — без регистрации, проектов и лишних настроек. Открыл утром → записал → закрыл вечером с чувством выполненного.

**Целевая аудитория:** частное лицо, которое планирует личные дела (дом, учёба, работа, покупки) и хочет один экран вместо блокнота.

*Домыслы:* пользователь открывает трекер на смартфоне утром и возвращается к нему в течение дня короткими сессиями (30 секунд — добавить или отметить задачу); вечерняя сессия — «что успел, что переносится». Задач в день — 5–15.

## 3. Что упразднено из заказа

- **Нативная кроссплатформенность (iOS/Android).** Требование «для айфонов и андроидов» исполняется через **адаптивное mobile-first веб-приложение** — работает в браузере обоих платформ без установки. Причина: рамки учебного кейса (веб-трекер).

## 4. Вопросы «клиенту» (гипотетические, с принятыми ответами)

1. **Какие поля у задачи обязательны?**
   → Только название. Всё остальное (заметка, время, приоритет) — опционально, чтобы добавление оставалось делом двух секунд.
2. **Что делать с невыполненными задачами в конце дня?**
   → Автоматически переносить на новый день с пометкой «перенесена». Ручное переписывание — лишняя работа.
3. **Нужны ли приоритеты и сколько уровней?**
   → Да, три уровня: низкий / средний / высокий. Мелкая, но полезная сортировка дня.
4. **Нужны ли аккаунты и синхронизация между устройствами?**
   → Нет. Это личный трекер: данные хранятся на устройстве (localStorage), никакого входа.
5. **Нужны ли напоминания и пуш-уведомления?**
   → Нет, вне MVP. (Зафиксировано в разделе «Вне скоупа».)

## 5. Роли пользователей и права

**Ролей нет — личное использование.** Один пользователь устройства без авторизации; полный доступ ко всем функциям.

## 6. Экраны и функции

### 6.1. Главный экран «Сегодня»

**Назначение:** единственный рабочий экран — обзор и управление задачами дня.

**Элементы:**
- **Шапка:** логотип «Дейлик», название, строка с датой («Сегодня, 3 ноября»).
- **Прогресс дня:** кольцо/полоса «выполнено N из M» с плавной анимацией при изменении.
- **Быстрое добавление:** поле ввода «Что сделать сегодня?» + кнопка «Добавить». Задача создаётся с приоритетом «средний» по умолчанию; рядом компактный выбор приоритета (три точки-переключателя).
- **Список активных задач** (карточки, отсортированы: высокие приоритеты выше, внутри уровня — по времени добавления). Карточка: круглый чекбокс, название, заметка (если есть, свёрнута до 1–2 строк), бейдж приоритета, время (если задано), кнопки «Редактировать» и «Удалить».
- **Секция «Выполнено сегодня»** (свёрнута, счётчик): зачёркнутые карточки с временем выполнения; кнопка «Очистить» (удаляет выполненные за сегодня).
- **Пустое состояние:** тёплая иллюстрация-плашка «На сегодня всё чисто ☀ Добавь первую задачу».
- **Секция «Ранние дни»** (внизу, свёрнута): выполненные задачи прошлых дней, сгруппированные по дате — история без отдельного экрана.

**Действия:** добавить задачу; отметить/снять выполнение (с анимацией); редактировать (открывает модальное окно 6.2); удалить (с анимацией исчезновения и отменой не усложняем — просто удаление); развернуть/свернуть «Выполнено» и «Ранние дни»; смотреть прогресс.

### 6.2. Модальное окно «Задача» (создание/редактирование)

**Назначение:** полный набор полей задачи.

**Элементы:** поле «Название» (обязательное), текстовая область «Заметка», выбор приоритета (низкий / средний / высокий — цветные радио), поле «Время» (тип time, опционально). Кнопки «Сохранить» и «Отмена». При создании задача привязывается к сегодняшнему дню.

### 6.3. Автоматическое поведение при смене дня

При открытии приложения, если сегодняшняя дата не совпадает с датой последнего открытия:
- все **невыполненные** задачи прошлых дней переносятся на сегодня (дата обновляется, ставится пометка «перенесена» — виден бейдж);
- выполненные остаются в истории «Ранних дней» со своей датой.

## 7. Данные

**Хранение:** `localStorage`, сервер данных не хранит (только раздаёт статику).

- Ключ: `daytracker.tasks.v1` — JSON-массив задач.
- Ключ: `daytracker.lastVisit.v1` — дата последнего открытия (для логики смены дня).

**Структура задачи:**

```json
{
  "id": "t-1730649600000-abc123",
  "title": "Купить корм коту",
  "note": "после 18:00, магазин у дома",
  "date": "2026-11-03",
  "status": "active",          // "active" | "done"
  "priority": "medium",        // "low" | "medium" | "high"
  "time": "18:30",             // опционально, HH:MM
  "createdAt": 1730649600000,
  "completedAt": null,          // timestamp выполнения
  "transferred": false          // задача перенесена с прошлого дня
}
```

**Демо-данные:** при самом первом запуске (ключ отсутствует) создаются 7 живых задач на сегодня — активные с разными приоритетами и временем + 2 выполненные, чтобы первый запуск выглядел наполненным. Повторный запуск с данными пользователя их не трогает.

## 8. Мини-брендбук

- **Название:** «Дейлик».
- **Характер стиля:** живой, тёплый, энергичный.
- **Палитра:**
  - `#FF6B35` — основной акцент (энергичный оранжевый, «мандарин»)
  - `#FFB347` — вторичный (тёплый янтарный); градиент бренда `#FFB347 → #FF6B35`
  - `#FFF7EE` — фон страницы (тёплый крем)
  - `#FFFFFF` — карточки
  - `#2D2A26` — основной текст (тёплый графит)
  - `#8A8177` — вторичный текст (приглушённый)
  - `#58B368` — успех, низкий приоритет
  - `#FFB347` — средний приоритет
  - `#E5484D` — высокий приоритет, удаление
- **Шрифт:** Nunito (округлый, тёплый; Google Fonts, веса 400/600/700/800) с системным fallback `system-ui, "Segoe UI", Roboto, sans-serif` — приложение не ломается без сети.
- **Логотип:** солнце с галочкой на градиенте (`info\logo.svg`); используется в шапке и как favicon.
- **Форма и фактура:** крупные скругления (12–16 px), мягкие тени с тёплым оттенком, достаточно воздуха.

## 9. Требования к адаптивности

- **Mobile-first:** базовая вёрстка под 360–430 px — основной сценарий.
- **Tablet (≥ 768 px):** шире рабочая область, карточки компактнее по вертикали.
- **Desktop (≥ 1024 px):** контентная колонка по центру (макс. ~640 px), комфортный «планшетный» ритм — трекер дня не превращается в многооконный.
- Сенсорные цели ≥ 44 px, отсутствие горизонтального скролла на всех контрольных ширинах.

## 10. Критерии готовности MVP (проверяемые)

1. Приложение открывается по адресу `http://localhost:3001` после одной команды запуска.
2. При первом запуске видны 7 демо-задач (первый запуск не пустой).
3. Задачу можно добавить с главного экрана за одно действие (Enter или кнопка).
4. Задаче можно задать заметку, приоритет и время через модальное окно.
5. Отметка выполнения: карточка зачёркивается, уходит в «Выполнено», прогресс дня обновляется.
6. Выполнение можно снять — задача возвращается в активные.
7. Задачу можно отредактировать и удалить.
8. Активные сортируются по приоритету; высокий — заметно выделен.
9. Данные переживают перезагрузку страницы (localStorage).
10. При смене системной даты невыполненные задачи прошлого дня автоматически переносятся с бейджем «перенесена».
11. Выраженные анимации: появление карточки, выполнение, удаление, движение при сортировке, прогресс.
12. Интерфейс на русском; вёрстка корректна на 360 px ширины и на desktop; без гориз. скролла.

## 11. Вне скоупа

- Пуш-уведомления и напоминания.
- Нативные iOS/Android-приложения и публикация в сторах.
- Аккаунты, вход и синхронизация между устройствами.
- Повторяющиеся/регулярные дела (рутина), календарь на неделю/месяц.
- Подзадачи, метки/категории, вложения.
- Офлайн-режим как отдельная фича (PWA/service worker).
- Тёмная тема.
